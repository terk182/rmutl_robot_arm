1. PPO คืออะไร

PPO (Proximal Policy Optimization) เป็นอัลกอริทึม Reinforcement Learning แบบ on-policy ที่พัฒนาโดย OpenAI ใช้สำหรับ train policy ให้เดิน/ทรงตัวได้โดยไม่ต้องมีตัวอย่างจากมนุษย์ จุดเด่นคือ เสถียร ง่าย และปรับได้ไม่ยาก จึงเป็น default ของงาน robot locomotion ใน Isaac Lab

หลักการทำงานโดยสรุป

  1. Collect (สัมผัสประสบการณ์) — ให้ policy ปัจจุบันเดินใน simulation เก็บข้อมูล (state, action, reward) ไปเรื่อยๆ
  2. Learn (อัปเดต) — เอาข้อมูลที่เก็บมา train หลายๆ epoch โดยใช้ PPO clipping เพื่อไม่ให้ policy เปลี่ยนเร็วเกินไป
  3. Repeat — วนซ้ำ เก็บข้อมูลใหม่ด้วย policy ที่ดีขึ้น
Policy state → ตัดสินใจ action → ลง simulation → ได้ reward
        ▲                                         │
        └────────── อัปเดต policy (PPO clip) ←──────┘

ทำไมต้องมี "clipping" ?

PPO จำกัดขนาดของการอัปเดต policy ในแต่ละครั้งด้วย clip_param (ที่นี่ = 0.2) โดยคำนวณ probability ratio ระหว่าง policy ใหม่กับเก่า: 

ratio = π_new(a|s) / π_old(a|s)

แล้ว clip ratio ให้อยู่ในช่วง [1-clip_param, 1+clip_param] ก่อนคูณกับ advantage ทำให้ policy ไม่ "กระโดด" ไปไกลจนพังในทีเดียว → แต่ละ iteration เปลี่ยนทีละนิด เสถียร

คำศัพท์สำคัญที่เห็นใน log ของ train:
Mean reward = ค่าเฉลี่ยรางวัลต่อ episode · Mean episode length = จำนวน step ที่หุ่นล้มช้า · Mean action noise std = ความสุ่มของ action (ยิ่ง train ยิ่งลดลง) · Mean value loss = ความคลาดเคลื่อนของ critic ในการประมาณ value

2. สถาปัตยกรรม Actor–Critic

ทั้งหุ่นเดิน Bimo และแขนกล 3DOF ใช้โครงสร้าง Actor–Critic แบบ standard ของ rsl_rl เหมือนกัน:

Actor (Policy) ทำหน้าที่ ตัดสินใจ รับ observation → คืนค่า mean ของ action (normal distribution)
MLP [256,128,64] · ELU
Critic (Value) ทำหน้าที่ ประเมิน รับ observation → คืนค่า value (สถานะนี้ดีแค่ไหน) ใช้คำนวณ advantage
MLP [256,128,64]
Policy Distribution Action ออกมาเป็น Gaussian (mean จาก actor, std จาก init_noise_std) ระหว่าง train จะสุ่มตาม distribution นี้เพื่อสำรวจ

รูป: โครงข่าย Actor–Critic ของ Bimo — obs 11 ค่า เข้า Actor (ตัดสินใจ) และ Critic (ประเมินค่า) แยกกัน

ทำไม Actor กับ Critic ใช้โครงสร้างเดียวกัน?
ที่นี่ตั้ง hidden dims ให้เท่ากัน [256,128,64] เพื่อให้เรียนรู้ความซับซ้อนของงานได้เท่ากัน แต่ Critic ไม่ได้ต่อ obs normalization (critic_obs_normalization=False) เพราะ critic เรียนรู้ value ที่เป็นค่าสัมบูรณ์ ไม่ต้อง normalize เหมือน policy

3. Runner Config — ควบคุมการรัน train

มาจาก BimoPPORunnerCfg(RslRlOnPolicyRunnerCfg) ในไฟล์ agents/rsl_rl.py

พารามิเตอร์ค่าความหมาย
num_steps_per_env16จำนวน step ที่เก็บข้อมูลต่อ env ต่อ iteration (rollout)
max_iterations500จำนวนครั้งที่อัปเดต policy (1 iteration = เก็บ + เรียนรู้)
save_interval50ทุก 50 iteration จะ save checkpoint model_*.pt
experiment_namebimo_ppo_rsrlชื่อโฟลเดอร์ log/checkpoint (อยู่ใน logs/rsl_rl/)
empirical_normalizationTruenormalize observation ด้วยค่า mean/std ที่เก็บจากข้อมูลจริง (robust กับ skala ต่างกัน)
fp16Trueใช้ mixed precision (half) ช่วยลด memory/เร็วขึ้น จำเป็นสำหรับ export ไป RKNN
obs_groups{"policy":["policy"],"critic":["policy"]}บอกว่า observation กลุ่มไหนใช้กับ actor/critic (ทั้งคู่ใช้ "policy")
หมายเหตุ max_iterations=500
งานเดินของ Bimo มัก converge ได้ภายใน ~500 iterations (ประมาณ 10–15 นาทีบน GPU ขนาดกลาง) ถ้า reward ยังไม่นิ่ง อาจเพิ่มเป็น 1000 ได้

4. Policy Config — โครงข่าย

มาจาก policy = RslRlPpoActorCriticCfg(...)

พารามิเตอร์ค่าความหมาย
init_noise_std1.0ค่า std เริ่มต้นของ action noise (ความสุ่มตอนเริ่ม train สูง → สำรวจเยอะ)
actor_hidden_dims[256, 128, 64]จำนวน neuron ของแต่ละ hidden layer ของ actor (3 ชั้น ลดลงเรื่อยๆ)
critic_hidden_dims[256, 128, 64]จำนวน neuron ของแต่ละ hidden layer ของ critic
actor_obs_normalizationTruenormalize observation ที่เข้า actor (ใช้สถิติ running mean/std)
critic_obs_normalizationFalseไม่ normalize obs ที่เข้า critic
state_dependent_stdFalsestd ของ action เป็นค่าคงที่ (ไม่เปลี่ยนตาม state) — ง่ายกว่า/เสถียรกว่า
activationeluactivation function ของ hidden layer (ELU ไม่มี dead neuron เหมือน ReLU ตอนค่าเป็นลบมาก)

ทำไม hidden dims เป็น [256,128,64] (ลดลง)?

ยิ่งชั้นลึกขนาดเล็กลงเรื่อยๆ ช่วยให้โมเดลบีบข้อมูลจาก observation ไปสู่ action ได้แบบ hierarchical โดย 256 มี capacity พอสำหรับงาน locomotion เบาๆ แต่ไม่ใหญ่เกินจน overfit/เทรนช้า (สังเกตว่า distillation student เล็กกว่ามาก ≈ [64,32] เพื่อให้รันบน MCU ได้)

5. Algorithm Config — PPO hyperparameters

มาจาก algorithm = RslRlPpoAlgorithmCfg(...)

พารามิเตอร์ค่าความหมาย
value_loss_coef1.0น้ำหนักของ value loss (เทียบกับ policy loss)
use_clipped_value_lossTrueใช้ clipping กับ value loss ด้วย (กัน critic กระโดด)
clip_param0.2ขอบเขต clipping ของ policy ratio (ค่าน้อย = อัปเดตช้าและเสถียร)
entropy_coef0.005น้ำหนัก entropy bonus — ยิ่งมากยิ่งสุ่มสำรวจ (balance exploration/exploitation)
num_learning_epochs10จำนวน epoch ที่ train ต่อ 1 iteration บนข้อมูลที่เก็บมา
num_mini_batches4แบ่งข้อมูลออกเป็นกี่ mini-batch ระหว่าง train (เพิ่ม stochastics)
learning_rate3e-3อัตราเรียนรู้ของ optimizer
gamma0.99discount factor — ให้ความสำคัญกับอนาคตไกลแค่ไหน
lam0.95GAE λ — ถ่วงน้ำหนักระหว่าง bias/variance ของ advantage
max_grad_norm1.0ค่า grad clipping (กัน gradient explosion)
scheduleadaptiveปรับ learning_rate ตาม KL divergence อัตโนมัติ
desired_kl0.01ค่า KL ที่ต้องการ — ถ้า KL มากไป ลด lr, ถ้าน้อยไป เพิ่ม lr

ภาพรวมการอัปเดตต่อ iteration

1. เก็บ (num_steps_per_env=16 steps × N env)  →  ได้ batch ประสบการณ์
2. แบ่งเป็น num_mini_batches=4
3. train num_learning_epochs=10 epoch
   - คำนวณ advantage ด้วย GAE (gamma=0.99, lam=0.95)
   - อัปเดต actor+critic ด้วย gradient (clip 0.2, lr 3e-3 adaptive)
   - เติม entropy_coef=0.005 เพื่อกระตุ้นการสำรวจ
4. เช็ค KL → ปรับ learning rate ตาม desired_kl
5. ทุก save_interval=50 → บันทึก checkpoint

6. Observation & Action Space

กำหนดใน bimo_task_env.py → BimoEnvCfg

Observation (11 ค่า)

กลุ่มจำนวนรายละเอียด
IMU orientation3roll, pitch, yaw (จาก quaternion_to_euler) — scale เป็น [-1,1]
Last commanded positions8ตำแหน่ง servo ทั้ง 8 ตัวล่าสุด — scale ตาม servo_min/max

obs = [roll, pitch, yaw, servo_1..servo_8] (11 ค่า)

Action (8 ค่า)

รายละเอียดค่า
ServosRHip, LHip, RShoulder, LShoulder, RKnee, LKnee, RAnkle, LAnkle
Action คือposition delta (องศา), clip ที่ [-3, 3]
นำไปใช้new_pos = last_pos + action × (4/3) แล้ว clip ตาม servo_min/max
ที่ตั้งค่ามาจากโค้ด:
servo_min = [-90, -90, -12, -90, 0, 0, -93, -93]
servo_max = [90, 90, 90, 12, 140, 140, 93, 93]
stand_pose = [-30, -30, 0, 0, 60, 60, 30, 30]

7. Distillation Policy (สำหรับ RP2040)

ถ้าอยากให้หุ่นเดินได้โดยไม่ต้องต่อ PC การใช้ PPO teacher (ใหญ่เกินไป) จะไม่ไหวกับ MCU จึงใช้ distillation บีบความรู้จาก teacher ลง student ตัวเล็ก

พารามิเตอร์ค่าความหมาย
student_hidden_dims[64, 32]student เล็กมาก พอรันบน RP2040 ได้
teacher_hidden_dims[256, 128, 64]teacher ตัวเต็ม (PPO ที่เทรนแล้ว)
loss_typemseใช้ Mean Squared Error เปรียบเทียบ action ระหว่าง teacher/student
gradient_length16ความยาว gradient ที่ไหลย้อนกลับ (ให้ student เลียนแบบหลาย step)
load_run / load_checkpoint.* / model_.*.ptโหลด checkpoint ล่าสุดของ teacher มาให้ student เลียนแบบ

เส้นทางใช้งาน: train PPO → distill student → export student เป็น policy.onnx → ใช้ onnx2c แปลงเป็น C → compile เข้า firmware RP2040

รูป: Knowledge Distillation — Teacher [256,128,64] ถ่ายทอดความรู้ให้ Student [64,32] ด้วย MSE loss

8. จาก train → export → ใช้งานจริง

ขั้นตอน

ขั้นคำสั่งผลลัพธ์
1. Trainisaaclab.bat -p scripts/.../train.py --task Bimo --num_envs 2048 --headlesscheckpoint model_*.pt
2. Exportisaaclab.bat -p scripts/.../play.py --task Bimo --num_envs 1 --headlesspolicy.onnx ใน logs/rsl_rl/bimo_ppo_rsrl/<run>/exported/
3. Copyคัดลอก policy.onnx ไปที่ working dirพร้อมใช้งาน
4. Runpython nn_walk.pyหุ่นเดินตาม policy

ตอน inference (nn_walk.py)

ses = onnxruntime.InferenceSession("policy.onnx", providers=["CUDA", "CPU"])

loop ทุก 50ms:
  state = bimo.request_state_data()
  obs   = process_observations(state["orient"], last_actions)   # 11 ค่า
  act   = ses.run(None, {input: obs.reshape(1,-1)})             # [1,8] delta
  new   = process_actions(act, last_actions)                    # บวกเข้ากับตำแหน่งเดิม
  bimo.send_positions(new)
  last_actions = new
ข้อควรระวัง: observation ที่ใช้ตอน inference ต้องตรงกับตอน train (เรียงลำดับและ scale เหมือนกัน) ไม่งั้น policy จะทำงานผิดเพี้ยน

9. 🤖 แขนกล 3DOF — ปรับใช้กับโปรเจกต์ terk_arm_esp32_v1

โครงสร้าง PPO ทั้งหมดที่อธิบายข้างต้น (Actor–Critic, Runner, Algorithm) ใช้ได้กับแขนกลเหมือนกัน — ต่างกันแค่ Observation / Action Space และขนาดโครงข่ายที่เล็กกว่า เพราะงาน “เอื้อม–คีบ” ง่ายกว่างานเดินทรงตัว

เปรียบเทียบ Bimo (หุ่นเดิน) vs แขนกล 3DOF

หัวข้อBimo (หุ่นเดิน)แขนกล 3DOF (terk_arm)
ObservationIMU 3 + servo 8 = 11มุมข้อต่อ 3 + gripper 1 + เป้าหมาย x,y,z 3 = 7
Actionservo 8 = 8 (delta)Δθ₁, Δθ₂, Δθ₃ + gripper = 4 (delta)
hidden dims[256, 128, 64][128, 64] (เล็กลง — งานง่ายกว่า)
SimulatorIsaac Lab (Bimo task)MuJoCo (Reacher) หรือ Isaac Lab
Target อุปกรณ์RP2040 (MCU)ESP32 (หรือ PC)

Observation & Action ของแขนกล (แนะนำ)

obs = [θ1, θ2, θ3, gripper, target_x, target_y, target_z] (7 ค่า)

action = [Δθ1, Δθ2, Δθ3, gripper] (4 ค่า) → new_pos = last_pos + action × scale แล้ว clip ตาม servo_min/max

Policy Config ที่แนะนำสำหรับแขนกล

actor_hidden_dims   = [128, 64]     # แขน 3 แกนไม่ต้องใหญ่เท่า Bimo
critic_hidden_dims  = [128, 64]
init_noise_std      = 1.0           # เริ่มสำรวจเยอะ
clip_param          = 0.2
entropy_coef        = 0.005

Reward ที่แนะนำ (ตัวอย่าง)

+ เข้าใกล้เป้าหมาย (ระยะห่างระหว่างปลายแขนกับเป้าหมายลดลง)
+ คีบจับสำเร็จ (gripper ปิด + วัตถุติด)
− ปลายแขนเกินขอบเขตการทำงาน (outside workspace)
− ใช้เวลา / พลังงานมากเกินไป
Deploy ลง ESP32:
train ใน MuJoCo / Isaac Lab → export policy.onnx → แปลงเป็น C (onnx2c / TFLite Micro) → รันบน ESP32 → สั่งงานผสานกับ /api/move ที่มีอยู่แล้วในโปรเจกต์ (ดูหัวข้อ RL & Sim ในเว็บสื่อการสอน)
ใช้คู่กับ Kinematics: ปกติยังใช้ IK กำหนดเป้าหมาย (หัวข้อ Kinematics ในเว็บ) แล้วให้ PPO เรียนรู้ “การควบคุมละเอียด” เช่น หนีบของนุ่ม หลบสิ่งกีดขวาง — ทั้งสองอย่างใช้คู่กันได้

10. พารามิเตอร์มีผลต่อพฤติกรรมยังไง

อยากได้...ปรับดังนี้
เดินได้เร็วขึ้น / ท่าทางก้าวร้าวขึ้นลด entropy_coef (เช่น 0.001) หรือเพิ่ม learning_rate
เดินช้าลง มั่นคงขึ้นเพิ่ม entropy_coef + ลด learning_rate
policy ไม่เสถียร / reward แกว่งลด clip_param หรือ learning_rate หรือหยุดใช้ empirical_normalization
อยากให้หุ่นเดินได้นาน (ไม่ล้ม)ปรับ reward weights ใน bimo_task_env.py (เช่น เพิ่มน้ำหนัก height/joint pos)
โมเดลเร็วกว่าตอน inferenceลด hidden dims ของ actor หรือใช้ distillation student
